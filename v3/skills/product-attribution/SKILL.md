# SKILL: product-attribution（产品视角经营归因 · 只写归因,不渲染）

给"产品视角经营归因分析"写**归因文字**。数据已由后端算好放在 JSON 里(子系列识别 + 下钻 + 9 因素);
**你只负责读数据 + 写归因,把归因写回 JSON 的「归因」键。渲染由后端做,你不碰 docx/html。**

主轴 = 产品子系列。后端已识别出若干**亮点**(同比增量金额涨最多)和**问题**(跌最多),每个都挂了
下钻(地市/区县/代理商/服务商的涨跌贡献)和 9 因素数据。你的任务:**解释每个子系列为什么涨/跌,
归因到哪些因素,是良性还是恶性,该关注什么。**

## 🚨 铁律

1. **数字禁止自己算**。所有数字(货值/增量/同比/台数/库龄/铺货…)都在 JSON 里,引用直接 copy,不要重算。
2. **数字必有出处**。归因里每个数字 / 地市 / 代理商 / 服务商名,必须能在该切片的 `下钻` 或 `因素`、
   或顶层 `经营背景` / `全量子系列` 里找到。
3. **区分良性 / 恶性**。下滑不一定是"没做好":可能是**品类换代**(被新品替代)、季节性、主动收缩。
   要结合因素判断,**别一律归咎执行**。上涨也分"健康放量"vs"低基数起量":
   **看切片头部 `同期_万` —— 同期_万≈0 且 增量≈货值 = 低基数新品起量,别夸大成"健康规模化放量"**;
   同期已有规模、同比仍正增,才是健康放量。
4. **要敢下判断 + 落到行动**。归因不是复述数据,是给**结论(为什么)** + **关注点(怎么办)**。
   归咎要落到可行动的点(哪个地市 / 代理商 / 因素 / 库存)。
5. **跨切片联动**。一个子系列的涨常对应另一个的跌(换代替代)。读 `全量子系列` + 所有切片,
   识别这种结构性主线,尤其**同地市此消彼长**(A 子系列某市涨 ≈ B 子系列同市跌)。
   ⚠️ 写"同地市此消彼长"前**务必回两侧 `下钻.地市` 各查一次**,确认是同一个地市名、一涨一跌,勿凭印象配对。

## 输入

JSON: `/sandbox/output/work/attribution.json`,结构:
- `_meta`: 范围 / 周期(period_start~end) / 同期(yoy) / 环期(mom)
- `全量子系列`: 全部子系列的 `货值_万 / 同期_万 / 环期_万 / 同比 / 环比 / 增量_万`(全景,用于判断联动)
- `经营背景`(区域级,当期 vs 同期,解释大盘环境):
  - `推广会`: 场次 / 签到公司 / 转化客户 / 券50解锁金额 / 会后红包金额 / 夜视王上线台数
  - `跑动`: 拜访次数 / 覆盖服务商 / 大华打卡次数
  - `业务员红包`: 红包使用金额 / 发放客户数 / 转化激活客户 / 平均解锁率 / 带来上线金额
  - `门头`: 年份 / 投入服务商 / 投入金额_万 / 激活数 / 带来上线金额_万(年度滞后数据,ROI 参考)
- `亮点子系列`[] / `问题子系列`[]: 每个含
  - 头部: `子系列 / 货值_万 / 增量_万 / 同比 / 环比 / 台数 / 同期_万 / 环期_万`
  - `下钻`: `地市 / 区县 / 代理商 / 服务商` 各 `{跌幅Top:[...], 涨幅Top:[...]}`(按增量_万排,每条带 增量_万)。
    ⚠️ **区县仅供你内部判断;正文引用出处只用 地市/代理商/服务商**(报告佐证表不展示区县,引区县读者找不到出处)
  - `因素`:
    - `铺货`: 当期/同期 {铺货台数 / 铺货金额_万 / 覆盖下级服务商}
    - `安装红包`: 当期/同期 {上线台数 / 中奖台数 / 中奖金额 / 覆盖服务商}
    - `备货`: {盘库季度 / 在库台数 / 在库货值_万 / 平均库龄天}(最新季度快照;库龄长=滞销积压)
    - `服务商画像`: {购买服务商总数 / 竞品TOP数 / 新签数 / 激活数 / 平均本年交易频次 / 客户分类分布}
  - `归因`: null ← **你写这个**

## 你要写的键(键名必须完全一致,否则渲染丢失)

### 1) 顶层 `J['总览归因']` = {
- `综述`: 字符串数组,2-3 条。大盘本期定性(整体靠什么涨 / 被什么拖累)、最大亮点 + 最大问题点名。
- `主线`: 字符串数组,1-2 条。跨产品结构性主线,尤其**产品换代**(某新品涨 ↔ 某老品跌、同地市此消彼长)。
}

### 2) 每个切片 `J['亮点子系列'][i]['归因']` 和 `J['问题子系列'][i]['归因']` = {
- `定性`: **一句话**给性质。如"被双光替代的良性换代,非执行问题" / "健康规模化放量" / "执行掉队,需介入"。
- `归因归咎`: 字符串数组,2-4 条。按因素拆解为什么涨/跌,**每条带证据数字**(引用下钻/因素)。分主因/次因、良性/恶性。
- `关注点`: 字符串数组,1-2 条。可落地的行动或提醒(具体到地市 / 代理商 / 库存 / 可复制的打法)。
}

## 归因怎么写(示范 — 对"问题子系列"里的 红外)

```
定性: "被双光替代的良性换代,非执行问题"
归因归咎: [
  "主因=品类被双光替代。双光增量+992万,且同地市此消彼长:杭州 双光+303/红外-252、宁波 双光+228/红外-99(见双光下钻.地市),客户主动升级、非丢单。",
  "渠道已顺势停推:红外铺货仅232台(双光3667,因素.铺货),但备货仍压10639台/191万、库龄483天(因素.备货)——换代期渠道积压。",
  "非营销缺位:安装红包照发(上线12438/中奖金额5.9万,因素.安装红包)也救不动,印证品类衰退而非投入不足。"
]
关注点: [
  "红外下滑不应归咎业务执行,是技术换代必然,顺势收尾即可。",
  "重点处理渠道191万积压(库龄483天):促销/调拨消化,防呆滞坏账。"
]
```
注意它做到了:**敢定性(良性换代)、跨切片联动(双光↔红外同地市)、证据全有出处、关注点可落地(消化积压)**。

再看一个**亮点侧**示范(演示用 `同期_万` 区分健康放量 vs 低基数起量):

```
定性: "健康规模化放量(非低基数):同期_万 已有 609万规模、同比+163%,是真增长"
归因归咎: ["主因=渠道铺货全面跟进:当期铺货3667台/60万(同期0)、覆盖227服务商(因素.铺货)","次因=红包强驱动:上线82957台/中奖42万(因素.安装红包),库龄仅90天周转健康(因素.备货)"]
关注点: ["西湖区(+106万)/滨江区(+100万)标杆打法,可向增速低的绍兴/台州复制"]
```
**反例**:若某子系列 增量+50万 但 `同期_万` 仅 2万(增量≈货值),那是**低基数新品起量**,定性写"低基数起量,需观察可持续性",别写成"健康放量"。

## 流程

```python
import json
P = '/sandbox/output/work/attribution.json'
with open(P, encoding='utf-8') as f:
    J = json.load(f)

# 1) 先通读全局:全量子系列前十几个(看谁涨谁跌,找换代配对) + 经营背景(大盘环境)。print 出来看。
# 2) 再逐个亮点/问题切片:读它的 下钻(哪些地市/代理商/服务商贡献涨跌) + 因素(铺货/红包/备货/画像)。
# 3) 写总览归因 + 每个切片归因,遵守铁律,每个数字带出处。
J['总览归因'] = {'综述': ["..."], '主线': ["..."]}
for s in J['亮点子系列'] + J['问题子系列']:
    s['归因'] = {'定性': "...", '归因归咎': ["..."], '关注点': ["..."]}

with open(P, 'w', encoding='utf-8') as f:
    json.dump(J, f, ensure_ascii=False, default=str)
print("✅ 归因已写回")
# stdout 再输出一句本期核心结论(最大亮点 / 最大问题 / 换代主线)。
```
