# SKILL: product-series-report (v3 — 双 HTML 输出)

> ⭐ **先读 `/sandbox/skills/system-overview/SKILL.md`**(口径单一真相源)。

## 报告定位

以「**产品子系列-新**」为主轴的产品维度经营报告,**每次生成两份 HTML**:

| 文件 | 大小 | 用途 |
|---|---|---|
| **概览版**`产品维度经营报告_概览_{域}_{时段}.html` | ~ 40 KB | **简短汇报**(给领导 5 分钟扫一遍),纯问题清单 |
| **全量版**`产品维度经营报告_v4_{域}_{时段}.html` | ~ 3 MB | **详细分析**(自己挖),全量数据 + JS 交互筛选 |

概览版顶部带跳转链接到全量版。所有数据从同一份 `data.json` 出。

## 🚨 七条铁律

**1. 产品主轴 = `install_redpack_v` / `product_flow_v` 的 `产品子系列-新`。** 不要用粒度更粗的 `产品系列`。

**2. 三级归类按 mode**(`国内产品线三级` 与 `产品子系列-新` 不严格 1:1,~5% 行会被误归;报告里注明)。

**3. 双口径分轨。**

| 维度 | 用哪张表 |
|---|---|
| 全省/地市/区县/代理商/价格/矩阵 | **`product_flow_v.最新分销价`(🌐 全量感知)** |
| 服务商/渠道健康度 | **`install_redpack_v.产品现有分销价`(🎯 红包扫码)** |

**4. 同环比对称(不用长基线)。**
- 评估期 = 用户选(period_start, period_end)
- 同期 = 评估期 - 12 月
- 环期 = 紧邻评估期前 N 月(N = 评估期月数)

**5. 服务商标识只保留 🎭 马甲(`vest_account`)+ 🚫 已关闭(`closed_provider`)**,不放算法启发式(低效签约 / 伞形)。
**马甲全表 EXCLUDE**(不进任何服务商表),🚫 已关闭**保留并标记**(可视化)。

**6. 砍掉:跑动效能 + 红包章节**(本版报告不分析)。

**7. 评估期默认 4 个月**(如 2026-01 ~ 2026-04)。短窗口同环比不稳,长窗口太重。

## 概览版结构(简短汇报用)

```
封面 + 元信息 + 顶部跳转 V4 的 callout

一、Top 10 子系列 — 问题清单
  10 张卡片,每张:
    - 子系列名 + 三级 + 评估期货值 + 同期 + 同比 + 均价同比
    - 问题点(1-4 条,emoji + 一句话)
    - 状态评级:🔴 严重 / 🟡 告警 / 🟢 健康

二、11 地市 — 问题清单
  11 张卡片,每张:
    - 地市 + Top10 子系列下滑/增长数 + 同期净流入 + 当期 Top10 货值
    - 问题点(子系列下滑 / 渠道净流出 / 高增亮点)
    - 状态评级

三、Top 30 区县 — 问题清单(按 Top 10 子系列总货值降序)
  30 张卡片(精简):区县 + 货值 + 总同比 + 主要问题

四、Top 20 代理商 — 问题清单
  20 张卡片:代理商 + 货值 + 总同比 + 主要问题
```

### 状态评级阈值

| 级别 | 触发(任一即可) |
|---|---|
| 🔴 **严重** | 同比 ≤ -20% / 渠道净流出 ≤ -20 / 整体腰斩 ≤ -50% / ≥3 子系列严重下滑 |
| 🟡 **告警** | -20% < 同比 ≤ -5% / 均价同比 ≤ -10% / 1-2 子系列下滑 / 价涨 ≥ +30% |
| 🟢 **健康** | 无触发(可能有高增亮点) |

### 问题图标含义

| 图标 | 含义 |
|---|---|
| 🚨 | 腰斩级下滑(同比 ≤ -50%) |
| ❌ | 严重下滑(-50% < 同比 ≤ -20%) |
| ⚠️ | 轻度下滑(-20% < 同比 ≤ -5%) |
| 💰 | 价格下降(均价同比 ≤ -10%)|
| 💲 | 价格上涨(均价同比 ≥ +30%)|
| 🗺️ | 多地市下滑(≥3 个地市同比 ≤ -20%)|
| 📉 | 渠道净流出(同期净流入 ≤ -20)|
| 🟡 | 渠道微缩(同期净流入 ≤ 0)|
| 📈 | 高增亮点(同比 ≥ +30% 或 多地市高增) |

## 全量版结构(详细分析 / V4 交互版)

```
1. 全省总览
   1.1 SO 总量(双口径同环比 5 列)
   1.2 全量子系列总览(三级下拉筛选 + 搜索 + 排序)

2. 全量产品 × 区县(搜索 + 排序)

3. 全量产品 × 代理商(搜索 + 排序)

4. 全量服务商汇总(去马甲)(地市下拉 + 标识下拉 + 搜索 + 排序)

5. 子系列 × 11 地市透视矩阵(子系列多选 checkbox + 货值/同比矩阵)

6. 渠道健康度(同环比对称)
   6.1 全省集合数
   6.2 11 地市矩阵
   6.3 同/环 × 新增/流失 全量名单(4 张折叠,每张带筛选)

7. 重点子系列:夜视王2.0(KPI + 4 张交互表)

8. 重点子系列:4G(同上)

9. 行动计划
   9.1/9.2 全省级专项(自动触发)
   9.3 各地市 Top 30 服务商行动(11 地市折叠,每家给"推夜视王/推4G")

10. 分析能力声明
```

### 全量版交互能力

- 点表头排序(任意字段升/降切换)
- 多列搜索框(服务商名 / 区县 / 代理商 模糊匹配)
- 单列下拉筛选(地市 / 标识 / 三级)
- 子系列复选框(章 5 透视矩阵动态加减)
- 筛选状态条实时显示"显示 X / Y 行"

## 重点跟进的两个子系列(可改)


如要换,改 runner 顶部常量;概览版会自动跟进(基于 Top 10),全量版章 7/8 会单独展开。

## 数据流

```
SQLite DB (product_flow_v / install_redpack_v / vest_account / closed_provider)
   ↓ runner.py
data.json (~4 MB,全量数据)
   ↓ html_overview.py + html_v4.py
概览 HTML(~40 KB) + V4 HTML(~3 MB)
```

## 输入参数

```python
params = {
    'period_start': '2026-01',
    'period_end':   '2026-04',
    'city':         None,      # None = 全省;否则单城市
}
```

对照期自动计算。

## 输出文件命名

```
产品维度经营报告_概览_{city or 全省}_{period_start}_to_{period_end}.html
产品维度经营报告_v4_{city or 全省}_{period_start}_to_{period_end}.html
```

两份在同目录,概览版顶部 callout 包含 V4 文件名链接(`<a href="{v4_filename}">`)。

## 自检清单

### Runner 出 data.json

1. ✅ 评估期 / 同期 / 环期 都用 SQL 查准(不依赖 pandas 二次算)

## 工作流

```bash
# 1. 跑 runner 出 data.json(全量)
python3 product_report_runner.py --period-start 2026-01 --period-end 2026-04

# 2. 出 V4 全量版
python3 product_report_html_v4.py --data <data.json>

# 3. 出概览版(传 V4 文件名做跳转链接)
python3 product_report_html_overview.py --data <data.json>

# 4. 用户:
#   - 简短汇报 → 打开 概览 HTML
#   - 钻细节   → 概览页点跳转 → V4 HTML
```
