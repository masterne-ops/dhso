# 转化漏斗管理系统 · 产品化说明

> 版本：2026-08-30  
> 定位一句话：**复杂转化的管理系统——管的是跳，不是待办。**

---

## 1. 产品定位

给那些**结果不靠单点任务、而靠多级转化叠出来**的管理者——  
把漏斗每一跳的转化率、关键手段和目标差距，收成一张可录入、可复盘、可传承的工作台。

| 维度 | 说明 |
|------|------|
| **品类名** | 转化型管理 / 漏斗管理系统 |
| **核心对象** | 漏斗的「跳」：转化率 × 关键因素 × 目标差距 |
| **不是什么** | 不是待办清单、不是纯 BI、不是 OKR 文档、不是甘特项目工具 |

---

## 2. 目标客户

### 2.1 抽象定义

**转化型管理者**：对「多级转化叠出来的结果」负责，而不是只对一串待办负责的人。

业界没有单一职称，常见落点包括：渠道/区域负责人、增长与转化负责人、销售管道负责人、招生/招聘漏斗负责人等。品类对外用「转化型管理者」，对内举例用具体职衔。

### 2.2 典型场景

事务结构是**漏斗型**而非线性：渠道下沉、销售管道、获客转化、招聘/招生、分阶段交付等——有阶段、有转化、有手段、要复盘。

### 2.3 管理痛点（感受向）

| 痛点 | 具体感受 |
|------|----------|
| 不知道卡在哪一跳 | 月底只看见「还差多少」，开会却在吵动作够不够——像堵车却只有「晚到」，没有哪段塞车 |
| 动作很多，转化不动 | 周报全是会议与活动，柱子不动——油门踩满，车速不变 |
| 目标与过程两张皮 | 上面盯年底家数，下面报本周流水——左手成绩单、右手流水账，中间没有等式 |
| 好办法传不下来 | 隔壁做成了，自己只能听故事——经验像烟，人走方法归零 |
| 怕遗漏，又怕一锅粥 | 判断散落在群聊和备忘录——脑子是唯一数据库，复盘像考古 |
| 复盘变成追责 | 没有「当时押的是哪一跳、哪个因素」——不是复盘，是审讯 |
| 层级一对齐就打架 | 省/市/区各说各话——三个计算器三个答案 |

## 3. 产品逻辑

### 3.1 五块核心

```
目标（存量/缺口）
    ↓
漏斗（层级 + 转化率）
    ↓
关键因素（手段，挂在「跳」上）
    ↓
记录（想到就写：待办 / 问题 / 思考）
    ↓
复盘（日推进 · 周校准） + 因素库（手段传承）
```

### 3.2 原则

1. **终点看差距，过程看转化**  
   全年（或项目终点）目标与缺口是主账；各跳转化率说明功做在哪；月/周节奏是过程辅看，不是第二套终点目标。

2. **手段必须挂在跳上**  
   关键因素是某一跳转化率的可操作杠杆，不是散装 KPI。

3. **想到就记，且记在正确位置**  
   承诺不是记全宇宙，而是：凡与转化相关的判断与动作，都有地方落，且落在对应跳与周期上。

4. **在转化率上做功**  
   选跳 → 看转化与短板 → 调因素与动作 → 再看是否拉动该跳。

5. **经验可迁移**  
   关键因素库沉淀可被采纳的手段模板；分享的是手段结构，不是他人私密待办。

6. **复盘可随时回放**  
   任一历史周期，漏斗、因素、笔记、待办仍在；复盘必答三问——差在哪一跳？手段做没做？下周期改什么？

## 4. 标准用法（产品主航道）

整条产品体验按四幕推进，UE 应始终让用户知道「我在第几幕」。

| 幕 | 用户动作 | 系统交付 |
|----|----------|----------|
| **① 立模型** | 上传目标表；用问答描述管理场景 | 漏斗层级模型（可一眼呈现） |
| **② 接通数** | 提供各跳转化率公式、取值逻辑、计算所需表格 | 每一跳可计算的转化率 |
| **③ 日运转** | 看待办、记录手段与判断 | 动作落在指定跳上；每日可提示待办 |
| **④ 周复盘** | 看短板跳、因素是否拉动、目标差距 | 调整下期因素与待办；有效手段可沉淀入库 |

**一句话用法：** 先建漏斗，再接通转化，然后按日推进、按周校准。

### 时间语义（必须写进产品说明）

| 粒度 | 用途 |
|------|------|
| **日** | 待办推进、提示 |
| **周** | 录入与复盘（动作与因素发生在周） |
| **月/阶段** | 目标账本与差距（复盘时的「账」） |

日与周是两种 UX 模式，不是两个并列菜单。

## 5. 能力地图（产品化模块）

| 模块 | 能力 | 用户价值 |
|------|------|----------|
| **建模向导** | 目标表 + 场景问答 → 漏斗阶 | 快速从「我有一张表」到「我有一张能管的漏斗」 |
| **转化接通** | 公式、取值逻辑、数据映射 | 转化率可信、可复算 |
| **漏斗工作台** | 层级柱、跳转化、短板提示 | 一眼看到卡点 |
| **关键因素** | 自动取数 + 手工补录；绑定跳 | 手段可执行、可核对 |
| **目标与差距** | 终点目标、完成率、差距；节奏辅看 | 主账清楚，过程可安排 |
| **日待办** | 按跳聚合的待办/问题 | 每天知道动哪一跳 |
| **周复盘** | 跳 × 因素 × 差距 → 下期动作 | 校准而不是追责 |
| **思考笔记** | 判断与意图外置 | 复盘有证据 |
| **因素库** | 手段模板采纳与沉淀 | 组织经验可传承 |
| **管辖与对齐** | 多级责任边界；下级目标卷积（参照） | 对齐口径，不改写本级目标 |

## 6. 体验原则（解决「能用但不像完整产品」）

当前系统能力可支撑运转与复盘，产品化重点是 **用主航道串模块**，避免功能墙。

1. **状态机，不是功能墙**  
   未建模 → 未接通 → 运转中 → 复盘日；每态只强调一件主任务。

2. **配置与使用分离**  
   建模/接通走向导；日常进工作台；避免同一屏既像后台又像作战室。

3. **打开即有一句**  
   - 首次：「把你的目标表变成一张能管的漏斗。」  
   - 平时：「今天动哪一跳、待办是什么。」  
   - 复盘：「这周哪一跳在拖后腿，下步改哪个因素。」

4. **成功态可见**  
   日/周结束时，用户能看到「本周关注跳是否改善、待办是否闭环」，而不是关页即散。

5. **数据诚实**  
   自动数、目标表、手填补洞——人机分工说清，不装作全自动决策引擎。

## 7. 与现有实现的关系

本仓库 `funnel/` 已具备工作台主体能力：漏斗与转化、关键因素、目标差距、待办/问题/笔记、周月周期、管辖总览、因素库等。

| 产品主航道 | 现状 | 产品化缺口（体验层） |
|------------|------|----------------------|
| 立模型 | 层级与目标可用 | 缺「目标表 + 场景问答」建模向导 |
| 接通数 | 生产库/公式在工程侧 | 缺用户可理解的接通向导与映射说明 |
| 日运转 | 待办已有 | 缺「今日」主视图与按跳提示 |
| 周复盘 | 周期与完成情况已有 | 缺一页式周复盘收束（三问） |
| 因素库闭环 | 可采纳 | 复盘结束「送有效因素入库」可加强 |

**产品化路径：** 不推翻重做，而是把现有模块挂到「建模 → 接通 → 日推进 → 周复盘」脊柱上，补向导与复盘收束，形成完整产品感。

---

## 8. 非目标（边界）

- 不替代通用项目管理 / 纯日历待办  
- 不替代企业级数仓与随意即席分析  
- 不做「自动替用户决策」的黑盒；诊断与建议服务于管理者拍板  
- 因素库不做社交灌水，只做可采纳的手段结构

---

## 9. 成功标准（产品化是否成立）

1. 新用户能否在向导内完成：**目标表 → 漏斗模型 → 至少一跳转化接通**  
2. 运转中用户能否不培训就回答：**今天动哪一跳、待办是什么**  
3. 复盘时能否用三问收束，并留下下期动作  
4. 组织内是否出现：**手段从库中采纳 → 本地见效 → 回写库** 的案例  
5. 用户是否感到：**这是一件完整的事**，而不是一堆报表和入口

## 10. 对外可用短述

**定位**  
复杂转化的管理系统：管的是跳，不是待办。

**给谁**  
转化型管理者——结果靠多级转化叠出来。

**干什么**  
把目标变成漏斗，把转化接通到数，用关键因素在指定跳上做功；按日推进，按周复盘；有效手段进库可传承。

**何以不同**  
待办工具不管转化；BI 不管手段落点；本文把 **跳、手段、差距、复盘** 绑在同一工作台上。
