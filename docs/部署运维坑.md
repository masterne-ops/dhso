## ⭐ 坑 1:scp 中文/emoji 文件名「静默失败」(最隐蔽)

**现象**:改了 page 代码、commit 了、`scp` 了、scp 还报"成功",但**生产根本没更新**,页面继续报旧 bug。

**根因**:macOS 文件名用 **NFD**(分解式 Unicode),Linux 用 **NFC**(组合式)。
`pages/32·📄 SMB周报.py` 这种带中文+emoji 的文件名,`scp` 从 macOS 传到 Linux 时字节跟生产的 NFC 文件名**不匹配** → 没覆盖原文件(可能生成个 NFD 新文件,或静默没传),scp 仍返回成功。

**正解(二选一)**:
1. **用 `deploy.sh`**(rsync 全量同步,已加指纹校验) —— 推荐,见坑 2
2. **手动部署必须**:ASCII 临时名 + 生产端 `glob` 覆盖 + md5 验证
   ```bash
   scp "本地/pages/32·📄 xxx.py" root@SERVER:/tmp/p.py     # 传 ASCII 临时名
   ssh root@SERVER 'cp /tmp/p.py /opt/so-data-analytics/src/pages/32*.py'  # glob 匹配真实文件名覆盖
   # 必须 md5 验证:
   md5 -q "本地文件"  ;  ssh root@SERVER 'md5sum /opt/.../32*.py'
   ```

**铁律**:含中文/emoji 文件名的部署,**scp 报成功 ≠ 真成功**,必须 md5 对比验证。

## 坑 2:部署优先用 deploy.sh,别手动 scp 单文件

`deploy.sh`(在项目根)用 **rsync 全量同步**,本来就避开 scp 单文件的 NFD/NFC 坑,还带:
- 重启服务 + 公网健康检查(HTTP 200)
- **代码一致性指纹校验**(本 session 新加,catch pages/ 静默失败)

用法:
```bash
./deploy.sh          # 同步代码 + 重启 + 健康检查 + 指纹校验
./deploy.sh --ops    # 顺带更新运维脚本
./deploy.sh --db     # 顺带同步 DB(压缩传输 + sha256 校验)
```
> 本 session 一直手动 scp 单文件图快,才踩了坑 1。**以后部署走 deploy.sh。**

## 坑 3:中文 SQL 不要 ssh 内联,用文件

`ssh root@SERVER 'sqlite3 db "SELECT ... 中文列名 ..."'` —— 双层引号 + 中文/特殊字符转义地狱,反复报错。

**正解**:写 `.sql` 文件 → `scp` → `sqlite3 db < file.sql`。

## 坑 5:删/改数据前**必须备份**

删/全量替换生产数据前,先 cp 备份(命名带日期 + 用途):
```bash
ssh root@SERVER 'cp /opt/.../product_flow.db /opt/.../product_flow.db.bak-用途-$(date +%Y%m%d-%H%M%S)'
```
本 session 每次大改都备份了 → 0 事故。备份保留到用户确认新数据 OK 再删。

## 坑 6:数据变更后重启清 streamlit 缓存

`@st.cache_data` 会缓存旧数据。改完数据**必须重启**才在页面生效:
```bash
ssh root@SERVER 'systemctl restart so-data-analytics'
```

## 坑 7:Excel 入库列名映射,小心重复列名 → 用位置映射

`provider_contract`(源 360 P6)有**重复列名**(专项金额/台数 `.1/.2/.3` 后缀)。
- **列名映射**会丢这些列(文件原始重复名 vs 表后缀名对不上)→ 全量替换后变 NULL
- **正解**:这类表用**位置映射**(文件第 i 列 → 表第 i 列),前提是文件与表列顺序 1:1 对齐(先 diff 确认)
