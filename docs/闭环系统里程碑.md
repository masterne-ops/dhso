# SO 闭环管理系统 — 里程碑计划

> 创建：2026-07-19
> 目标架构：openclaw 多 agent 协同
> 原则：里程碑驱动，每步独立可用，不追求大而全

## 核心模型

```
SI ∝ SO = 服务商数量 × 交易率 × 客单价
交易率 = f(有效跑动率, 营销触达率, 价格到位率)  ← 待建模
```

详见 [[so业务因果模型]]

---

## M1：公式落地 + 异动自动诊断

**目标**：系统自动输出「谁掉了、掉在哪个因子」，不需要人翻数据。

**交付物**：
- [ ] SO 三因子拆解逻辑（服务商数 × 交易率 × 客单价，可按代理商/城市计算）
- [ ] 环比异动归因：三因子各贡献了多少变化量
- [ ] 输出格式：异动归因表（代理商维度）

**不含**：第二层归因、动作追踪

**预估**：2-3 周

---

## M2：动作数据接入 + 相关性初建

**目标**：把动作指标和交易率关联起来，验证哪些动作显著相关。

**交付物**：
- [ ] 动作数据盘点（跑动频次、推广会参会、红包到位率，覆盖度评估）
- [ ] 关联表：代理商维度，动作指标 × 结果指标
- [ ] 相关性排名输出：哪些动作和交易率提升最显著相关

**不含**：因果归因、自动派任务

**前置**：M1 完成
**预估**：4-6 周

---

## M3：闭环 MVP — 诊断→建议→追踪

**目标**：最小可用闭环，跑在 openclaw 多 agent 架构上。

**交付物**：
- [ ] 诊断 agent：异动归因 + 动作关联 → 自动定位问题
- [ ] 方案 agent：基于相关性输出 top 1-2 管理动作建议
- [ ] 追踪 agent：动作执行率 → 结果改善验证 → 闭环

**前置**：M1 + M2 完成，openclaw 架构就绪
**预估**：M2 后 2-4 周

---

## 架构演进路径

```
当前：Streamlit 看板 + 手动周报 + skill（battle-plan / 诊断）
  ↓ M1
增加：自动异动归因模块（仍在 Streamlit 内）
  ↓ M2
增加：动作-结果关联分析模块
  ↓ M3
迁移：拆成独立 agent，跑在 openclaw 上，人只管决策
```
