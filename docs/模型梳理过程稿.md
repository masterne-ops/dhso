# SO 闭环管理模型 — 问题梳理过程稿

> 2026-07-19 开始 · 目标：通过问题梳理推导出业务模型，而非先验设计
> 方法：提问 → 讨论 → 摘录关键结论 → 模型自然成形

## 已确认的背景共识

- 管理链路：省区（金总）→ 一级代理商(~49家) → 服务商(~9,339家) → 终端
- 现有工具：SO数据看板、周报自动生成、代理商诊断 skill —— 都停留在「看结果」层
- 目标形态：动作派发 → 达成率追踪 → 结果有效率验证 的闭环
- 约束：金总一人精力有限；数据质量参差；系统必须"能用起来"而非"设计完美"
- 终态架构：openclaw 多 agent 协同

## 梳理中的关键问题

### Round 1：从真实场景出发（2026-07-19 提问，待答）

1. **最近一个真实案例**：最近一次你发现某个代理商/城市 SO 出问题时，具体发生了什么？你当时是怎么一步步查的、最后做了什么动作？（用一个具体案例讲，越具体越好——哪个代理商、什么时间、你怎么发现的、查了什么、最后怎么办的）

2. **现在的管理节奏**：你每周/每月固定做的管理动作是什么？（比如周会、看报表、给业务员派任务？）哪个环节最耗你的精力？

3. **你最想要的**：如果这个系统只能帮你解决一件事，你希望是哪件？

## 摘录 · 关键结论

### Round 1 回答：杭州 SO 同比不及预期案例（2026-07-19）

**金总的假设定位链条：**
```
杭州SO同比不及预期
  └─ 没有明确的重点攻坚目标 → 销售资源撒胡椒面
       ├─ 原因A：大销量客户当前条件谈不下来（不敢/没能力攻坚）
       └─ 原因B：于是资源全压在中腰部（也是农村包围城市，但要看时间和产出）
  └─ 根因 = 战略不清晰
```

**三类攻坚目标客户（明确的名单画像）：**
1. 海康核心金牌二级
2. TPlink、宇视等品牌一级代理
3. 海康一级代理
> 选择依据：看他们的销量、与品牌的绑定关系。以终为始——要在杭州突破就必须搞定这类客户；当前条件不成熟就创造条件、额外付出，但即使投入也要强调性价比、ROI。

**核心战略判断（金总原话要点）：**
- 整个生意中最核心、最稀缺的资源 = **能直接接触业主的、有采购量的服务商**
- 攻坚上述渠道的本质目的 = **低成本获取现有服务商**（不是为攻坚而攻坚）

**识别出的两个缺失（模型要补的洞）：**
1. **服务商单元模型没有建立**（站在代理商视角）：
   - 一个服务商的获客成本是多少
   - 年采购量是多少
   - 产品组成是什么
   - 毛利率是多少
   - 费用是多少
2. **打法没有建立**：
   - 不同类型服务商的单点打法没有成形
   - 样板点打完后，没有形成「有固定成功率的复制战法」

**⚠️ 对模型形状的重要影响：**
原 M1 设想（SO=服务商数×交易率×客单价 的分解诊断）只覆盖了「执行追踪层」。
杭州案例揭示出上面还有三层：战略层（资源投向）→ 单元经济层（服务商值多少钱）→ 战法层（怎么打、成功率多少）。见下方「模型分层推导」。

**Round 1 未答：** Q2 管理节奏、Q3 只做一件事 —— 待后续补。

## 模型分层推导（由杭州案例牵引出来）

```
┌─────────────────────────────────────────────┐
│ 战略层：资源投向哪里？                          │
│   攻坚(三类名单) vs 中腰部，按 ROI 分配          │
│   判断依据 = 单元模型 + 打法成功率               │
├─────────────────────────────────────────────┤
│ 单元经济层：一个服务商值多少钱？                  │
│   获客成本 / 年采购量 / 产品组成 / 毛利 / 费用    │
│   分类型建立（安装商/工程商/门店/竞品TOP…）      │
├─────────────────────────────────────────────┤
│ 战法层：怎么打下来？                             │
│   打法库（按服务商类型）→ 样板点 → 复制战法       │
│   关键指标 = 固定成功率                          │
├─────────────────────────────────────────────┤
│ 执行追踪层：动作做了没？结果来了没？              │
│   SO = 服务商数 × 交易率 × 客单价（分解诊断）    │
│   动作达成率 × 结果有效率（原 M1-M3 闭环）       │
├─────────────────────────────────────────────┤
│ 数据层：现有 SO 库（80表+6视图，双口径）          │
└─────────────────────────────────────────────┘
```

**推论：** 原 SO 公式没有错，但它只是「执行追踪层」的骨架。
杭州案例说明金总的真痛点在上面三层——尤其是单元经济层：
没有单元模型，「攻坚 vs 中腰部」就只能凭感觉，无法比较 ROI。

**数据可行性初步判断：**
- 年采购量、产品组成 → 现有库可算（install_redpack/product_flow/provider_contract）
- 获客成本 → 需把「动作投入」分摊到服务商（跑动工时难量化，但营销费用/红包投入已有 marketing_* 表）
- 毛利率、费用 → 代理商侧数据，金总手里可能拿不到 → 单元模型 V1 可能只能做「采购量口径」，毛利口径待补
- 三类攻坚名单 → competitor_top_provider 已有 71 家海康金牌（攻坚起点已存在）

### Round 2 回答（2026-07-19）

**1. 毛利口径锁定：基准毛利 = 8%**
- 背景：总部定价表按定价卖没有利润；代理商实际利润来自返利，但没有明确政策规定返利多少打成本、多少算利润
- 决策：**单元模型 V1 统一用「代理商卖货给服务商毛利率 8%」作为基准毛利**
- 含义：单客年毛利 = 年采购额 × 8%（采购额口径即可算，不必等代理商真实账本）

**2. 萧山是反面典型 → 模型新增「真实性」维度（重大结论）**
- 事实：萧山6月快速起量名单中很多客户不真实——疑似代理商为完成指标，拿服务商的号扫码上线
- 推论：**SO 数据会被博弈，不能直接当真。** 单元模型和 SO 公式里的「服务商数」必须先过真实性校验
- 待细化：金总人工判断造假时用的信号是什么？→ 要变成数据规则（见 Round 3 问题）

**3. 攻坚客群优先级锁定：71家海康金牌 = 第一类且最重要的客户**
- 理由：真实、有量
- 单元模型先为这批客户建出来
- 该表已有字段：竞品体量_万（25年竞品分销安防体量）→ 份额抢夺空间可算

### Round 3 回答（2026-07-19）

**1. 真实性判断靠人访谈，不靠数据 → 系统职责重新定位（重要设计原则）**
- 萧山造假是金总**和代理商访谈聊出来的**，不是数据看出来的
- 推论：系统**不能判定真假，只能出嫌疑名单**。数据模式（突然放量/月底集中/无复购/GPS异常）→ 嫌疑标记 → 人访谈确认 → 确认结果反哺嫌疑规则库
- 这本身是一个小闭环：**嫌疑识别 → 人工核实 → 规则迭代**

**2. 获客成本 = 不知道 → 这正是模型要跑出来的核心产出（任务定义转变）**
- 金总原话："这是一个核心任务，就是要把模型跑出来"
- 推论：获客成本不是模型输入，是模型**输出**。系统要能按攻坚客户计量投入（跑动×费用×让利），并追踪到转化
- 两条路径：
  - **回溯法**：已转化的客户，用现有 visit_record 回看从接触到转化的跑动投入 → 第一批获客成本估算（不需要新数据）
  - **前瞻法**：费用/让利类投入目前无记录机制 → 需建轻量投入登记（待 Round 4 确认决策流程）

**3. 「打下来」的定义锁定：连续N个月稳定月采购≥X万，不是偶尔小单**
- 具体 N、X 数值待定（Round 4 提案确认）
- 注意：这与真实性维度呼应——一次性放量不计入转化，天然过滤萧山式造假

### Round 3.5：金总的思考路径 —— 切换经济学（2026-07-19）

**原话逻辑链：**
> 核心稀缺资源是服务商 → 我们就是用多少资源去交换这些服务商 → 无非是利润。
> 海康金牌二级卖海康产品能赚多少钱，换大华能不能赚更多钱。
> 切换成立条件：**切换后收益 > 切换前收益 + 切换成本**。
> 切换成本最大的组成 = 阻力问题（海康在业主端的影响力/品牌拉力）。
> 切换成本很难估算。

**模型化：三层账**

| 视角 | 账 | 核心问题 |
|------|-----|---------|
| 服务商（金牌二级） | 卖海康毛利 S×m_h vs 卖大华毛利 S'×m_d，再扣切换成本 C | 切换值不值 |
| 代理商（一级） | 8%基准毛利 × 年采购量 vs 获客投入 | 拿下值不值 |
| 省区（金总） | 让渡利润（返利/政策/费用）vs SO增量价值 | 让多少合适 |

**交换的货币 = 利润。** 省区/代理商让渡利润 → 补足服务商切换成本 + 提供切换溢价。

**关键推论（应对"切换成本难估算"）：**
- 不做先验估算，做**后验测量**：真实切换成本 = 实际转化该客户付出的总让渡利润（回溯法，与获客成本合流）
- 决策框架改为：**让渡预算上限 = 切换毛利差 ΔM = 大华毛利 − 海康毛利**（毛利差可估，业内返点结构大致透明）
- 实际让渡多少能转化 = 打法问题，靠后验数据迭代
- 切换成本的差异化代理变量猜想：服务商类型决定品牌阻力大小——工程商（业主指定品牌）阻力大，门店/分销（自己决定卖什么）阻力小 → 待验证

### Round 5 回答：毛利差的真实结构（2026-07-19）

**金总的诚实回答（示意口径）：**
| | 进价 | 卖价 | 单台毛利 | 流速 |
|---|---|---|---|---|
| 海康 | 100 | 120 | 20 | 天然更快（品牌拉力） |
| 大华 | 80 | 110 | 30 | 慢 |

**核心修正：毛利差不能按单台算，要按「毛利 × 流速 = 单位时间利润」算。**
- 单台毛利大华占优（+10元/台）
- 但流速海康占优（业主端品牌拉力）
- **流速差就是切换成本的可观测表现**——品牌阻力不再抽象，它直接体现在台数差上

**推导出的切换决策规则：**
```
服务商年利润 = 单台毛利 × 年台数
切换成立：30 × Q_d > 20 × Q_h + C(一次性切换成本)
即：Q_d / Q_h > 2/3 + C/(30×Q_h)
```
→ 经验法则：**大华台数能达到海康的 2/3 以上，切换在毛利上就成立**（一次性切换成本另计）

**两类打法因此分叉：**
1. **补流速**（动销动作：业主端推广、帮服务商卖货）→ 缩小 Q_d/Q_h 差，可持续
2. **补利润**（让渡返利）→ 直接补偿总利润差，本质是花钱买客户，不可持续

**🔑 流速比今天就能测（不需要新数据）：**
71家里「在售大华=1」的部分切换客户 = 天然对照组。
流速比 = 大华实际月采购（库里有）÷ 竞品体量_万/12（表里现成）。
同一客户同时卖两个品牌 → 最真实的流速差测量。

### Round 6 回答（2026-07-19）

**1. 对71家流速比的保留意见：采购行为可能不典型**
- 金总判断：71家的大华采购行为可能不是典型行为（少量试单/挂名采购会污染流速比）
- 但同意跑分析验证："你可以分析一下看看"
- → 分析时必须区分「真实流速」和「挂名性零星采购」，结合转化定义（连续N月≥X万）过滤

**2. 费用流程现状：没有制度，一单一议（重要组织约束）**
- 现状：让利/费用**没有具体方案，一单一议**，无审批记录载体
- 深层原因：**公司毛利体系设计时假设大华品牌 = 海康品牌**，没有为「品牌切换成本」预留让渡空间
- 推论：
  - 前瞻法的投入侧数据**没有现成载体可接**——要么新建轻量登记（页面/表单），要么持续黑盒
  - 让渡利润实际从省区/代理商自己的毛利里挤，没有正式预算科目
  - 单元模型如果跑出了可信的获客成本数字，反过来可以成为向公司争取「品牌切换专项费用」的依据 → 模型的组织价值

**数据环境备注：** 本地 db/product_flow.db 为 0 字节占位文件，真实库在生产服务器 /opt/so-data-analytics/db/。分析需同步库文件到本地或远程执行。→ 已解决：SSH 直连服务器只读查询可行。

## 首次实证：71家金牌流速比分析（2026-07-19，2026-01~06 数据）

**口径**：大华采购 = install_redpack_v 与 product_flow_v 两口径逐月取大；流速比 = 大华月均 ÷ (竞品体量/12)；粗转化判定 = 活跃≥3月 且 近3月（04~06）月均≥2万

**核心数字：**
- 64/71 家（90%）2026年有大华采购记录 → **有渗透**
- 但 61/64 流速比 < 1/3，月均普遍 <1万 → **无流速**（金总预判"采购行为不典型"被验证）
- 在售大华=1 的 18 家全部有真实采购，但月均 0.02~0.76万 → **"挂名在售、微量走货"**
- 大体量基本没动：600万海威电子、300万朗旭、200万吴兴佳科/永康海泉 = 0 采购

**过转化线的只有 2 家，都在宁波，都是 25~30万中型客户：**

| 客户 | 竞品体量 | 大华月均 | 流速比 | 形态 |
|---|---|---|---|---|
| 宁波七尚智能 | 30万 | 7.74万 | 3.09 | ⚠️ 4~6月集中爆发（近3月月均15.47万），疑似冲量 or 真实放量，**待访谈核实** |
| 宁波华越智能 | 25万 | 2.14万 | 1.03 | ✅ 活跃6月持续型，最像真实转化，**回溯法第一样本** |

**实证得出的模型修正：**
1. 转化判定需加「时间分布均匀性」维度——Q2集中爆发型（七尚）vs 持续型（华越）要分开，防萧山式冲量混进来
2. 「渗透 ≠ 转化」要拆成两个指标：渗透率（有采购记录）已经90%，但转化深度极低 → 攻坚管理的核心矛盾不在"有没有卖"，在"有没有起量"
3. 当前真实转化形态：**大体量（≥200万）攻不动、中小体量（25~30万）可突破** —— 与"农村包围城市"直觉一致，现在有数据支撑了
4. 宁波是唯二产出转化的城市 → 宁波业务员/代理商做对了什么，值得拆解

## 🎯 收敛：金总提炼的三个核心问题（2026-07-19）

> 聊了几轮后的收敛。这三个问题 = 系统必须输出的三张答卷。

### 问题1：打谁 —— 以区县为单位的攻击名单 + 里程碑目标
- 名单要明确出来（不是模糊的"关注竞品客户"）
- 里程碑目标要整理出来：**多久、卖多少**
- 管理单位 = 区县

### 问题2：怎么打 —— 攻击对象画像 + 产品组合 + 政策
- 画像：什么样的客户是可打的（体量、类型、品牌绑定）
- 卖什么：产品组合（物料号级）
- 用什么政策：让渡结构（返利/费用/红包）

### 问题3：怎么放大 —— 样板点打赢后的可复制计划
- 样板点赢了不算完，要给出**可以放大的计划**
- 放大 = 固定成功率的复制战法（呼应 Round 1 的"打法没有建立"）

### Round 7：问题1的名单结构设计（2026-07-19 金总定）

**攻击名单用两个维度给服务商分类：**

| | 维度A：品牌×等级 | 维度B：画像类型 |
|---|---|---|
| 含义 | 他现在经营什么品牌、在该品牌体系里什么级别（如海康金牌/海康普通/混卖/大华专属） | 批发门店 / 中小工程商 / 安装商 / 夫妻门店（现有4类规范分类） |
| 捕捉什么 | 切换收益侧（体量、品牌绑定深度） | 切换成本侧（业态决定品牌阻力：工程商=业主指定阻力大，门店=自己说了算阻力小——待验证猜想） |
| 数据源 | provider_profile.主营品牌/监控主推品牌/是否HKTOP + competitor_top_provider.竞品体量 | provider_contract.客户分类（→category_mapping 规范4类） |

**推论：每个区县一张 品牌×画像 矩阵，格子就是攻击名单的分组单元。** 不同格子对应不同打法（产品包+政策包不同）。

**Round 7 数据验证结果（2026-07-19）：**

| 维度 | 全省字段 | 全省覆盖率 | 71家覆盖率 | 判断 |
|---|---|---|---|---|
| 画像 | provider_contract_v.客户分类_规范 | **100%**（未分类132家兜底） | 70/71 | ✅ 直接可用 |
| 品牌 | provider_profile.监控主推品牌（单选，值域干净） | 37.8% | 71/71（用 competitor_top.客户经营品牌兜底） | ⚠️ 金牌池满覆盖，全省需补档案 |

关键发现：
- 品牌维度**不要用「主营品牌」**（多值拼接串、70%含分隔符），**用「监控主推品牌」**（单选、值域收敛：海康5546/大华1215/TP908/宇视223…）
- 全省 6 成服务商品牌字段缺失 = 档案填写率问题（非数据质量）→ 金牌池先落地，倒逼一线补全省档案
- 71家两个维度接近满覆盖 → **名单矩阵可以立刻在金牌池上出第一版**
- 体量字段：provider_profile.主营品牌安防产品销售额（53.5%覆盖）比年安防采购量（43.1%）略好；71家池 95.8% 覆盖

### 矩阵的五个结构性发现（模型级结论）

1. **体量与渗透倒挂**：≥100万档12家/2200万（占总体量51%）→ H1采购仅21.6万、3家未触动；20-50万档35家/955万 → 贡献98.8万采购+全部转化。**当前打法能打进20-50万档，打不进≥100万档。**
2. **转化不发生在「海康+大华」混卖池**：18家在售大华客户0未触动、家家有采购，但17家卡微量（单家流速比<0.2）——**"混卖"≠转化，只是挂名试单**。2家真转化都在"其他组合"。
3. **最重的格子铁板一块**：纯海康×批发门店（9家/1210万）+ 纯海康×中小工程商（18家/840万）= 占全量47%，但 ✅0 🔥0。**最大存量机会 = 当前打法打不进去的地方。**
4. **画像冷热分明**：中小工程商32家/1750万，唯一同时有✅和🔥的画像 → **短中期主战场**；夫妻门店16家全部微量（触达到了、深度不够）；安装商最冷（H1合计仅14.4万）。
5. **城市错配**：杭州24家/1640万双第一但0转化（最大洼地）；宁波9家/335万拿下全部2家转化；金华3家/830万单家体量最大却只产出0.55万。

- **RFM 分层**：复用 src/_metrics_rfm.py 现有口径（R≤30活跃 / 9宫格 / V0-V4等级阈值），不另造

## 深耕两客群基本盘首跑（2026-07-19，2026H1数据）

> 全量数据与方案骨架见 docs/作战方案-深耕两客群.md，此处只记模型级结论。

**基本盘：** 批发门店795家有效（活跃49.9%，H1采购728.5万）；中小工程商2404家有效（活跃50.0%，H1采购1647.8万）。两客群H1都已达2025全年的82%。**两客群都有一半客户"签了不采"**（沉睡+零采购≈50%）。

**结构差异：**
- 批发门店 = 头部依赖：15家核心（1.9%）扛42%采购 → 防头部单点流失
- 中小工程商 = 腰部驱动：活跃层115家贡献37% > 核心层 → 1070家浅购池（活跃的9倍）是升级机器

**漏跑（高价值零拜访）：合计77家 / 277.8万可流失**
- 批发门店16家/78.6万；中小工程商61家/199.2万
- 工程商漏跑57%集中在5个分销商：万仞8家、常业8家、博飞8家、亿群6家、履泰5家 → 可按分销商下督办单

**重复跑（资源错配）：合计366家 / 2359次拜访**
- 浅购+零采购层被拜访≥4次：批发130家/896次、工程商236家/1463次；被≥3个业务员多方重复跑278家
- **77家高价值零拜访 vs 366家低价值高频拜访 → 跑动资源一次再配置即可补上大部分漏跑缺口**

**产品策略线索：核心买"方案"、浅购只买"枪机"**
- 两客群TOP3都是14/12/24走量系列；核心层第5名是高价值差异化品（批发：48系列+SDT球机；工程商：NVR H系列高单价录像机）；浅购层第5名都是WP低价系列
- **浅购客户只进前端摄像机、没进后端NVR → NVR配套是浅购→活跃升级最现实的交叉销售抓手**

**品牌绑定：两客群约2/3签约服务商主推仍是海康**（批发69.3%/工程商66.2%），大华主推仅16.7%/13.0% → 深耕战的转换空间
