关键设计:**数字准确性优先**——所有数据用 SQL 算好喂 JSON,不让 AI 写查询;AI 只负责拼装 + 写分析性的两章。

### gather_full_report(city, start, end) 的 18 维度
跑 3 时段(current/yoy同比/mom环比)× 部分维度:
- `so_overview`(SO总览:全量感知/安装红包双口径/绑定率)、`target_completion`(目标完成)、
  `district`(**区县下钻** ← 全省版要换掉)、`provider`(服务商画像+等级分布)、`visit`(跑动) — 这 5 个跑 3 时段
- 只跑当期:`lifecycle`/`keypoint_unvisited`/`redpack_roi`/`visit_efficiency`/`dispatch_alerts`/`salesperson_scope`/`activation_status`/`rfm_distribution`/`abnormal_providers`/`salesperson_eval`/`highlights`/`product_roi`
- 输出 JSON:`{地市, 时段, 数据{各维度}, 对比表{}, 核心结论, 数据完整性}`

### query 函数签名模式(全部写死 city)

全省版:去掉 city 过滤(WHERE 城市=? 删掉),或聚合所有城市。

| 维度 | 全省版处理 | 实现 |

### 3.2 🆕 11 地市排名(核心,替代区县下钻)

新函数 `query_city_ranking(conn, period, year)`,对每个地市算并排名:

| 指标 | 来源 |
|---|---|
| SO 金额(万) + 全省占比 | product_flow_v / install_redpack_v 按 上线城市 GROUP BY |
| SO 同比/环比 | 三时段对比 |
| 年度目标完成率 + YTD 进度 | kpi_targets(按城市汇总) + kpi_rhythm 节奏 |
| 活跃服务商数 / 激活率 | install_redpack 按城市 |
| 跑动覆盖 | visit_record 按城市 |

输出:
- 11 地市明细表(各指标 + 排名列)
- **红榜**(完成率/同比 Top 3)、**黑榜**(Bottom 3 / 未达标地市)
- 全省达标地市数 / 拖后腿地市清单

## 5. 关键技术细节

### query scope 改造(city → 全省)
地市版:`WHERE 上线城市 = ?`(参数 city)
全省版:删掉该 WHERE(或 `WHERE 上线城市 IS NOT NULL`),其余 SQL 不变。
⚠️ 注意有些表用 `上线客户地市`(install_redpack)、有些用 `上线城市`(product_flow_v),字段名不同,见 docs/数据库说明.md。

### 11 地市排名 SQL 思路
```sql
SELECT 上线城市 AS 地市,
       COUNT(*) AS SO台数, ROUND(SUM(最新分销价)/10000,1) AS SO万
  FROM product_flow_v
 WHERE 上线年月 BETWEEN ? AND ? AND 上线城市 IS NOT NULL AND 上线城市!=''
 GROUP BY 上线城市 ORDER BY SO万 DESC
```
完成率:JOIN kpi_targets(按城市 SUM(SO目标_万)) + kpi_rhythm 节奏(YTD应达成 = 目标×Σ节奏占比)。
参考 `_panorama.py` 的 §1 SO增长 已有完整的"年度目标/YTD应达成/完成率"算法(本 session 刚加的双进度条),直接抄过来按城市循环。

### 沙箱 V3 流程(page 10 后半)
page 10 import 了 `_code_agent`(run_agent/start_async_run/get_async_run_status/docker_available...),把 gather 的 JSON 写文件喂沙箱,沙箱 docker 里 AI 跑 SKILL 输出 docx。全省版照抄这段,换 SKILL 名 + JSON。
⚠️ 沙箱依赖 docker,生产要 docker 可用。先确认 `docker_available()`。
