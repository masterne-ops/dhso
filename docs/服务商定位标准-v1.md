# 服务商定位标准 v1（需求）

> 起草 2026-06-02 · 状态:**草案,待业务确认阈值后定稿**
> 目标:确立**唯一一套**服务商定位/分类标准,以后所有业务问题(派单、资源分配、渠道政策、攻坚选客)都用它,不再各模块各搞一套。
> 适用对象:`provider_*` 服务商(~9,339 家);本标准也是 RFM 模块、代理商评分、服务商全景等页面的上层口径基础。

---

## 1. 背景与问题

服务商定位先后用过 **RFM** 和 **波士顿矩阵**,都感觉「和实际业务对不上」。根因不是模型不好,是用错了场景,且把一个混合指标当成了一个轴:

- **RFM** 是零售/电商给消费者用的,只测「和我交易的历史行为」——只看到「份额」一面,且纯向后看。它不知道服务商的天花板多高,也不知道他是工程还是零售。能回答「谁活跃/谁流失」,给不出战略定位。
- **波士顿矩阵** 是给集团做业务组合投资的(市场增长率 × 相对市场份额),硬套到单个服务商身上两轴含义都糊了,分完「明星/瘦狗」不知道该干嘛。
- **「采购量」这一个指标里塞了两件事**:① 他自身的体量(天花板)② 他从我们采购多少(我方份额)。同样「年采购 5 万」,可能是大盘子只给我 5%(该猛攻),也可能是小店全给我(该维持)——战略相反。把这两件事合成一个数,就是「对不上」的根。

**结论:不是换一个更好的模型,而是把指标拆对、并对不同族群用不同模型。**

---

## 2. 核心结构:一棵树,先分族群,各走一套模型

服务商**不是同质的一群买家**。批发商本质是「渠道网络里的一个节点」,不是终端买家,用同一把尺子量不准。所以第一刀先分族群:

```
服务商
├─ 终端商  → 模型 A：场景(工程/零售/混合) × 潜力 × 份额  → 🎯攻坚 / 👑战略 / 🌱机会 / 🤝稳定
└─ 批发商  → 模型 B：网络规模 × 我方掌控 × 渠道风险      → ⚔️必争 / 🏛️命脉 / 👀观察 / 🪙稳定小盘
```

- **「层级」(终端/批发)是分流器**:先决定一个服务商走哪条评估流水线,再谈其他。
- **两个族群、两套模型,不是 N 个模型**。终端商内部(工程/零售/混合)共用模型 A。
- **一条主线串着两边**:「我占他采购多少 / 品类渗透」这个灵魂指标两族都问,只是分母不同(终端=他自己进货;批发=他的进货盘子)。所以不是两个割裂的世界,是一棵树的两枝。

---

## 3. 族群 A:终端商模型

终端商 = 直接面向最终用户(甲方/项目 或 个人/商铺)的服务商。用三个标签描述:

### 3.1 场景(选打法):工程 / 零售 / 混合

| 场景 | 终端 | 特征 | 打法关注点 |
|---|---|---|---|
| 工程 | 甲方 / 弱电项目 | 单笔大、波动、项目周期、品类集中在项目级设备 | 方案/投标支持、账期、项目级集采 |
| 零售 | 个人 / 商铺 / 个体户 | 小额高频、标品、施工与辅材占比低、付款简单 | 铺货、培训、售后、营销物料 |
| 混合 | 两者都做 | 兼具 | 按主营选主打法 |

**工程客户的判据 = 是否有「设备选型话语权」,不是是否自己投标。**
- 自己设计方案、自己投标的 → 工程客户。
- 不投标、从分包手里拿活,但**对用什么设备有话语权**的 → **也是工程客户**(而且常常性价比高:不养投标团队、轻资产,却能带货)。
- 完全没话语权的**纯施工/劳务队** → 不作为独立定位对象,他是工程商的下游。

### 3.2 潜力(选投不投、投多少资源):大 / 中 / 小

衡量这个服务商**自身的天花板**(年生意盘子),不是他从我们买多少。
> 起步沿用现有三档(大≈年采购10万+ / 中≈1万-10万 / 小≈0-1万),但**口径要从「从我采购」改成「他自身体量」**——见 §5 度量方法。

### 3.3 份额(选守还是抢):高 / 中 / 低

= 他从我采购 ÷ 他的总采购。回答「这个天花板里有多少已经是我的」。

### 3.4 战略矩阵(潜力 × 份额)

| | 份额低(我占得少) | 份额高(我占得多) |
|---|---|---|
| **潜力高** | 🎯 **攻坚** — 最该砸资源抢份额,增长就在这 | 👑 **战略** — 深耕保有,最高服务等级,别被撬走 |
| **潜力低** | 🌱 **机会** — 低成本试探 / 自助下单 | 🤝 **稳定** — 维持,效率优先,别过度投入 |

> 潜力保留大/中/小做资源分级;画矩阵时高=大、低=中小,2×2 最利落。场景在每个格子里选具体打法。

## 4. 族群 B:批发商模型

批发商 = **不直接面对最终用户**,把货卖给其他服务商(工程商、零售商)的中间层。他是**渠道乘数**:服务好 1 个批发商 = 间接覆盖他下游几十个小服务商。因此评估对象、管理逻辑、风险点都和终端商不同,**不能套模型 A**。

| | 终端商 | 批发商 |
|---|---|---|
| 评估什么 | 他的生意 + 我的渗透 | 他的**分发网络** + 我的掌控 |
| 怎么管 | 直接管他卖货 | 管他的**下游**——价格体系、区域、返利 |
| 核心风险 | 流失、不活跃 | **乱价砸盘、窜货、绑架下游换品牌**(终端商没有) |

### 4.1 三个维度

1. **网络规模** — 下游服务商家数、覆盖区域(对应终端商的「潜力」)。
2. **我方掌控** — 他的进货盘子里多少走我的货、品类渗透、是否主推我(对应「份额」)。
3. **渠道风险**(批发商独有) — 乱价/窜货记录、账期、是否有换品牌倾向。作为**预警叠加层**。

### 4.2 战略矩阵(网络规模 × 我方掌控)

| | 掌控低(没主推我) | 掌控高(主推我) |
|---|---|---|
| **网络大** | ⚔️ **必争** — 覆盖广却没拿下,最该攻、也最危险(他能带走下游) | 🏛️ **命脉** — 战略渠道,深度绑定 + 防乱价 |
| **网络小** | 👀 **观察** | 🪙 **稳定小盘** |

> 渠道风险不进矩阵,做红黄灯预警:任一象限里风险高就亮灯(尤其🏛️命脉若乱价,杀伤最大)。

## 5. 度量方法(基于现有数据,先估后校)

三个标签都能用现有库估出来。以下是逻辑口径,不含实现。

| 标签 | 主要数据来源 | 估算逻辑 |
|---|---|---|
| **层级(终端/批发)** | `distribution_info`(铺货 上级→下级)、`install_redpack`(上线)、`product_flow.出库客户类型/渠道客户类型` | 货大量**下发给下级服务商**且自身**上线率低** → 批发;货**直接产生上线**、下发占比低 → 终端。 |
| **场景(工程/零售)** | `product_flow`(出库金额、品类、上线地)、`install_redpack`(上线地点离散度) | 工程=单笔大/波动/品类集中项目级/上线地理聚集(一个项目装一批);零售=小额高频/标品/上线地点分散。可结合 `provider_profile`/标签 的业务员标注。 |
| **潜力(终端)** | `product_flow`、`install_redpack`、区县覆盖 | 自身出货量 + 上线量 + 覆盖区县数 + 品类齐全度反推天花板。 |
| **潜力(批发=网络规模)** | `distribution_info` | 下游服务商数量 + 下发总量 + 覆盖区域。 |
| **份额(品类渗透代理法)** | `product_flow.产品线一级/国内产品线一~四级` 按客户聚合 | 竞品采购看不见,用**品类渗透**代理:一个完整项目需 前端/存储/交换/线缆/智能 等品类,他从我们进了几类。品类越齐→份额越高;只买单品类→份额低、有隐藏钱包。 |
| **份额校验** | `域2 服务商.竞品TOP` | 若有竞品信息,可直接校验品类渗透代理法准不准。 |
| **渠道风险(批发)** | `product_flow.是否异省/异城/异县`、`剔除跨省报备`、`客户行为异常`、同物料号下单单价离散度 vs 分销价 | 大量**异地上线** + 跨省报备剔除 → 窜货信号;单价显著低于分销价/离散度大 → 乱价信号。 |

> 关键:**份额的分母(他的总采购)我们看不到**,品类渗透是「自家数据可算」的最佳代理。先用它跑,再用竞品TOP/业务员访谈校准。

## 6. 与现有模型的关系:分层,不冲突

按「变化速度」分层就清楚了:

| 层 | 工具 | 变化速度 | 作用 |
|---|---|---|---|
| **战略底座** | 本标准(层级 × 场景/网络 × 潜力 × 份额/掌控) | 慢(季/年) | **定位**,本文档 |
| **健康监控** | RFM(现有 page 01) | 快(周/月) | **预警**,不做定位:如「👑战略客户 90 天没下单」→红灯 |
| ~~业务组合~~ | 波士顿矩阵 | — | **退役**——潜力×份额矩阵就是给渠道重新校准坐标轴后的、更好用的「波士顿」 |

RFM 继续用,但定位为哨兵;波士顿不再单独使用。

## 7. 开放问题 / 待定稿项

1. **阈值标定**:潜力大/中/小的金额线、份额高/中/低的品类渗透百分比线,需用真实数据分布 + 业务员直觉校准,不能拍脑袋。
2. **场景判据细化**:工程 vs 零售的数据特征(金额阈值、上线地理聚集度)需跑数验证区分度。
3. **批发商潜力的数据缺口**:`distribution_info` 能否完整覆盖下游网络,需核实;不全则需业务员补录。
4. **混合体归属**:既批发又自己接工程的(前店后厂),按「对我们最大的价值/风险来自哪一面」归族群,主营归类 + 次要属性标注,不追求纯粹(80/20)。
5. **标签落库**:三个标签算出后写入 `provider_profile` / 服务商标签表,供所有页面统一读取(避免各模块各算各的)。
